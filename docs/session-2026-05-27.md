# Session notes — 2026-05-27

Working notes for resuming where we left off. Not a polished doc.

## What shipped today

**Provider integration**
- `openrouter` as a first-class provider for LLM, embeddings, and rerank (`internal/llm/llm.go`, `internal/embed/embed.go`, `internal/retrieval/rerank.go`)
- `OPENROUTER_API_KEY` + auto-light-up: when set with no other provider chosen, all three workloads default to `openrouter` with vendor-prefixed model slugs
- `HTTP-Referer` + `X-Title` attribution headers wired on every OpenRouter call

**Schema**
- Migration `0006_embed_dims_2048.sql` — embedding columns are now `vector(2048)` to support `nvidia/llama-nemotron-embed-vl-1b-v2:free` and similar. HNSW index dropped because pgvector caps HNSW at 2000 dims; sequential scan is fine at benchmark scale. Switch to `halfvec(2048)` for production scale.

**HTTP surface**
- `POST /v1/experience` — direct experience write, embeds inline, no extractor, no queue. Used by RAG-baseline benchmarks; also the right primitive for a future "Claude self-tagged memory" flow.
- `GET /v1/queue/pending?user=X` — `{extract_pending, embed_pending}` so callers can poll instead of sleep-and-guess.
- `HookEvent.OnlyRaw` — flag to restrict experience retrieval to `abstraction=0` (verbatim sources only). Required for evidence-grounded benchmarks; default off so context-injection callers keep getting summaries.
- Removed `/v1/capture` and `/v1/sessions/end` (no longer used by the new hook layout). Working-memory store layer kept because MCP tools still use it.

**Hook refactor — session-checkpoint model** (replaces the per-turn pattern)
- `SessionStart` — unchanged (read facts/experiences)
- `UserPromptSubmit` — retrieve only, **no per-turn ingest anymore**
- `Stop` + `PreCompact` — read transcript JSONL, POST to `/v1/ingest` as one source (kind `claude-session` / `claude-precompact`)
- New `readTranscript()` parser strips tool_use / tool_result, keeps user + assistant text only
- `PostToolUse → /v1/capture` removed entirely

**Consolidation correctness**
- Consolidation worker no longer calls `SupersedeExperience`. Sources stay active when a summary is created; lineage lives in `parent_id` + `meta.consolidated_from`. Critical fix — earlier behavior invalidated every source row when a summary was generated, silently breaking fact-grounded retrieval.

**Benchmark harness** (`scripts/longmemeval/harness.py`)
- `--ingest-mode {extract,raw}` — extract = full pipeline, raw = direct `/v1/experience` write (RAG baseline)
- `--dataset-format {longmemeval,locomo}` — LoCoMo adapter (snap-research/locomo10.json)
- `--user-prefix` honored by LoCoMo iterator
- Poll-based queue drain replaces fixed `--ingest-wait` sleep; `--ingest-wait` is now a hard upper bound
- Date grounding: experience hits get `[date: YYYY-MM-DD]` prefix; answerer gets "Today's date: ..." in system prompt
- Fixed `_throttle` IndexError on oversized prompts; fixed `render_hits` to extract nested experience/fact bodies

## Benchmark numbers (LoCoMo conv-26, 100 questions)

| Mode | Score | Wall time | Notes |
|---|---|---|---|
| RAG (raw) — pre date fix | 40/100 (40%) | 50 min | Many "yesterday"/"last week" answers judged wrong because no temporal anchor |
| RAG (raw) — with date fix | 62/100 (62%) | 50 min | Date prefix + answerer system prompt fixed temporal-class questions, +35 on multi-hop |
| RAG (raw) — post-consolidation-disaster | 53/100 (53%) | 59 min | ~9 points of judge non-determinism vs the 62 baseline |
| Extract (LLM-distilled) | 17/100 (17%) | 15 min | Extraction strips dates/verbatim quotes for thematic summaries; same failure mode as consolidation |

**Key finding**: LoCoMo measures verbatim-recall (right answer is a quoted date or phrase). Extraction and consolidation both compress for thematic relevance, which is the wrong shape for this benchmark. Both architectures are correct for *context injection* (small summary into every prompt), wrong for *evidence-grounded answering*. The benchmark doesn't measure what Anamnesia is actually designed to do.

## Goal / vision (per user)

Anamnesia as a personal AI substrate — a memory layer reachable from any AI agent (not Claude-Code-specific), supplying:
1. **Cross-project preferences** that follow the user between repos (coding styles, tool preferences)
2. **Per-project / per-customer knowledge** that builds up over time
3. **Proactive synthesis** — *"what did I do this week in project X"* + *"you might also want to mention Y"*
4. **Persona injection** — user defines a personality once, every AI session adopts it

Architecturally the bones are right: Postgres + MCP endpoint + facts/experiences/scope. The gaps are:
- Persona isn't a first-class slot in the SessionStart output
- No proactive synthesis surface (just similarity search today)
- No temporal-window query primitive on experiences (only sources)
- Privacy/multi-device story unsolved (fine for now — local laptop is the right starting deployment)

User intends to build other agents (phone-notes-while-walking, weekly-summary, etc.) as small Agent SDK apps that point at the same Anamnesia MCP endpoint. Anamnesia stays focused on being the memory primitive; each agent shape is a separate ~100 LOC SDK app.

## Open issues / cleanup worth doing soon

- **Consolidation worker is disabled in `.env`** (`ANAMNESIA_CONSOLIDATE_EVERY=9999h`). Re-enable once we have abstraction-aware retrieval defaults the way we want them. Current default retrieval still mixes abstractions; that's intentional for context injection but you should be aware.
- **Per-user DB state**: `locomo-conv-26` (38 raw experiences from RAG-mode runs) and `locomo-extract-conv-26` (126 facts + 9 experiences) are sitting in the DB. Either keep them for repro or wipe before the next round.
- **Schema doc**: `pkg/anamnesia/types.go` `Experience.Abstraction` is now load-bearing for retrieval correctness — worth a comment explaining the contract (0 = verbatim/raw, ≥1 = synthesis).
- **`/v1/queue/pending` endpoint** would benefit from a `project` filter too; today it's user-scoped only.
- **LoCoMo iterator** only yields `conv-26` because that's the first sample. Multi-sample runs aren't tested end-to-end — wall-time prohibitive without faster models or pool-of-N worker.
- **Extract worker is serial** (`for _, src := range pending { ex.Run(...) }` in `internal/jobs/worker.go:198`) — biggest production speedup lever, with the in-user-fact-race we discussed.
- **Custom internal eval** — none of the public benchmarks measure what Anamnesia is shaped for. Want ~30 hand-crafted scenarios scripted through hooks that test: preference persistence cross-project, project-scoped recall, weekly-summary quality, persona consistency. This is what should actually gate releases, not LoCoMo.
